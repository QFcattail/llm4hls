### 2. mermaid「LLM 调用标注法 v1」设计 + 落地（架构 v2.5）
- **问题**：原架构图只画控制流，路人看不出每次 LLM 调用注入了什么（信息从哪来）、输出什么、有什么权力（review 只选还是可驳回）
- **设计四条规范**：
  1. 节点分型：体育场形=LLM 调用（四行卡）/ 矩形=工具调用（标 credit）/ 圆柱=数据源（编号 D1-Dn）/ 子程序形=存档缓存 / 菱形=闸门
  2. **LLM 调用四行卡**：① 名称 ② 注入（内容+来源编号：D1-Dn 数据源 / #n 上游 LLM / 工具 / 缓存）③ 输出 ④ 职责权限
  3. 不画数据流虚线边（来源已在卡内编号），实线只走控制流——避免蜘蛛网
  4. **职责权限词汇表**：生成（无决策权）/ 选择（有确定性回退）/ 可驳回（reject 触发重生成）/ 硬门（非 LLM 确定性规则）/ 仲裁（非 LLM 存档判定）
- **落地**：`agent-architecture.md` 新增 §4.0 全流程总览图（5 个 LLM 调用全部四行卡标注）+ 读图示例（LLM#1b/#5b review「可驳回」有否决权 vs LLM#4 select「选择」能否决组合但失败不阻塞）
- **验证**：mermaid-cli 实际渲染 §4.0 图通过（mmdc 编译 + PNG 目视结构正确）
