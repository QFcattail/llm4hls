## 本次目标 (Goal of This Session)
用户提出三点优化决策质量问题：① DeepSeek 应该支持结构化输出，解析失败是不是我们调用方式不标准；② 仿真失败时仿真器会报原因，但回退不看原因直接回首选项；③ 评审 AI 应在选择前保证所有策略计划本身合理（策略可能名字好但计划带毒，如动签名）。

## 完成的工作 (What Was Done)

### 1. 事实确认（真机探针）
- **DeepSeek 原生支持结构化输出**：`response_format: {"type": "json_object"}` 实测返回干净可解析 JSON。此前自由文本+正则容错确实是非标调用打的补丁
- **select 真实决策证据**（回答"#5 是否真在决策"）：5 次真机选择中 3 次排除策略、1 次建三组合、理由字段具体——回退只在解析失败时发生且当时静默

### 2. 架构 v2.7（设计文档先行）
- §4.4 要点 + §8.1 接口更新，变更记录 v2.7

### 3. 结构化输出（v0.5.0）
- `DeepSeekClient.complete` 加 `response_format` 可选参数
- `HLSLLMClient._complete_json`：优先 JSON 模式，后端不支持时（TypeError）回落普通调用
- propose_strategies / select_strategies 改 JSON schema；`_parse_strategies` = JSON 优先 + 正则兜底（ScriptedClient 等非 JSON 后端不受影响）

### 4. 评审 AI 扩展为"可行性+兼容性"双审查
- select prompt 两步制：先逐策略可行性审查（接口不变/功能不破/可综合/资源不超），带毒策略进 rejected（含 why）；再从幸存策略选兼容子集
- 返回四元组 `(indices, reason, rejected, fell_back)`；解析失败重试一次，仍失败回退 `[0]` 且 `fallback=True`（**不再静默**，事件+TUI 可见）
- 真机验证（dotProduct）：评审 AI 否决"Unroll by 32 + Cyclic Partitioning"（"Cyclic partitioning on interface arrays changes top-level RTL interface"）并**级联否决**依赖它的"Adder Tree"策略——正是用户担心的"计划带毒"场景被提前拦下

### 5. 盲回退改失败感知回退
- `_try_opt_candidate` 返回 `(outcome, failure_feedback)`（csim/synth 失败时 build_feedback 蒸馏）
- 回退时 `apply_strategies(failure_feedback=...)` 注入"Previous attempt FAILED"块——LLM 知道上次栽在哪（如 HLS 207-6969 pragma 文件作用域）
- TUI：strategy_select 显示 `✗ rejected: <名字>` 和 fallback 警示
