- `Strategy` 加 `combinable_with` 字段；`_parse_strategies` 解析兼容性行；propose prompt 要求逐策略标注

### 3. TUI 实现
- `ToolErrorBar` 改**状态驱动渲染**：内部状态（策略区 `_strategy_all/_picked/_reason/_ready` + 工具区 `_tool_header/_tool_errors`）+ `_compose()` 拼接（策略区 ≤2 行 + 工具区填满剩余，截断显示"...and N more errors"，总行数恒 ≤5）；公开方法 `show_result`/`show_running`/`clear_bar` 签名不变，新增 `show_strategies`/`update_picked`/`clear_strategies`
- 关键防御：`_refresh_ui` 每 150ms 调 `show_running`，一次性 update 模式下策略行必被心跳擦掉——状态驱动后各 show_* 只动自己分区（TC-009 钉住）
- `app.py` 事件分发加 3 分支：`phase_enter("optimize")` 清工具区+显示策略就绪行；`strategy_select` 更新策略面板；`optimize_fallback` 改写 ▶ 行；`phase_exit("optimize")` 清策略区

## 遇到的问题与解决方案 (Issues & Resolutions)

| 问题 | 根因 | 解法 |
|---|---|---|
| TC-009 首断言失败 | 手算行数错：5 行内容区需为"and N more"留 1 行，错误预算 4 行实显 3 条 | 断言改为 3 条 + "and 4 more errors"（实现本就符合设计） |
| 心跳擦掉策略行的风险 | `_refresh_ui` 每 150ms 调 `show_running`，一次性 `update()` 会覆盖整栏 | ToolErrorBar 改状态驱动渲染，`_compose()` 每次从分区状态重建 |
| 评审 AI 输出不可控 | LLM 可能不按 `PICK:` 格式回、或选越界编号 | `_parse_pick` 宽松解析 + 非法一律回退 `[0]`，保证优化循环不崩 |
