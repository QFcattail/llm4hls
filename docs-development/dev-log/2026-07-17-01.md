## 完成的工作 (What Was Done)

### 1. TUI 仪表盘完整实现

从设计到实现，完成了完整的交互式 TUI 仪表盘：

**入口**：`fpga-agent.py`（一行启动）+ `run.sh`（自动 source Vitis + .env + venv）
```bash
./run.sh                    # 交互选题 -> TUI 仪表盘
./run.sh --task <path>      # 跳过选题
```

**选题界面**：纯 print+input（不用 Textual，避免两个 App 冲突导致黑屏），自动扫描 tasks/ 目录，支持输入外部路径。

**四区域仪表盘**（Textual + Rich）：
- **区域 A（FlowChart）**：5 阶段流程图，✅🔄⚪ 状态 + 耗时 + 统计
- **区域 B（ToolErrorBar）**：工具报错独立栏，解析 gcc 风格错误行（file:line:col: error:）+ Vitis 错误码 + test case 失败，过滤 INFO/WARNING 噪声，最多 5 行 + 剩余计数。工具运行时显示"🔄 正在运行... 已耗时 Xs"（每 150ms 实时刷新）
- **区域 C（ActivityPanel）**：LLM 流式输出。thinking 逐 token 实时刷新（Static 覆盖式）+ 完整行写入 RichLog；code 行缓冲 + cpp 语法高亮。两者在同一区域连续输出
- **区域 D（StatusBar）**：credit 进度条 + token 统计(含 reasoning) + 本环节调用次数 + review 意见，2 行精简

**退出确认**：按 q 弹对话框（y/n/enter/esc），不直接退出。

### 2. DeepSeek stream 模式

改 `deepseek_client.py` 加 `stream=True` + `on_stream` 回调。reasoning_content -> thinking（dim italic），content -> code（cpp 高亮），逐 token 推送到 TUI。

### 3. 关键 bug 修复

#### 3.1 VITIS_HLS_ROOT 路径不对
- **现象**：csim 全 compile_error (0.0s)，log 为空
- **根因**：harness config.py 默认 `/opt/xilinx/2025.2/Vitis`，实际装在 `/home/admin/Xilinx/2025.2/Vitis`
- **修复**：run.sh + fpga-agent.py 都 `export LLM4HLS_VITIS_HLS_ROOT=/home/admin/Xilinx/2025.2/Vitis`
- **验证**：修复后 csim 真跑（10.6s），log 有内容 `Test Case 1 Failed!`，SCORE 1.400

#### 3.2 TUI 黑屏
- **根因**：一个进程里连续跑两个 Textual App（PickerApp + AgentDashboard），第二个黑屏
- **修复**：选题改为纯 print+input，只有仪表盘用 Textual

#### 3.3 thinking 每 token 换行
- **现象**：思维链一行只显示几个字符
- **根因**：每个 token 都 `RichLog.write()`，每次 write 换行
- **修复**：thinking 用 Static 实时覆盖显示（逐 token 刷新不换行），完整行才写入 RichLog

#### 3.4 工具报错太笼统
- **现象**：只显示 `compile_error`，不显示具体错误
- **修复**：ToolErrorBar 独立栏，解析 gcc 行号错误 + 过滤 INFO/WARNING + 最多 5 行

#### 3.5 工具运行时无状态显示
- **现象**：csim/synth 执行期间看不到"正在跑"
- **修复**：heartbeat 检测工具 stage -> 记录开始时间 -> _refresh_ui 每 150ms 刷新 ToolErrorBar 显示真实耗时

#### 3.6 vitis-run 找不到时报错不明确
- **修复**：csim 返回 elapsed<0.5s + log 空 时判定环境问题，明确报"ENVIRONMENT problem, not a code bug"

#### 3.7 csim 前没让 LLM 先检查
- **现象**：上来直接 csim 原始代码，浪费 credit
- **修复**：第一次 csim 前先 LLM review+修复，LLM 能直接看出的 bug 不用花 credit 跑 csim

#### 3.8 run.sh set -u 和 Vitis settings64.sh 冲突
- **现象**：`PYTHONPATH: unbound variable`
- **修复**：`set -euo pipefail` 改为 `set -eo pipefail`

#### 3.9 max_tokens 截断推理模型
- **现象**：DeepSeek 返回空 content
- **根因**：max_tokens=16384 包含 reasoning_tokens，太小被推理吃光
- **修复**：max_tokens 默认 None（不限制），用 thinking.reasoning_effort 控制推理强度
