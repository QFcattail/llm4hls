## 追加（同日，TUI 真终端修复）v0.3.1

**问题**：用户在服务器 `./run.sh` 选题后 TUI 启动即崩：`TypeError: object Text can't be used in 'await' expression`。

**根因**：v0.3.0 给 ToolErrorBar 新增的组合方法命名为 `_compose()`——**与 Textual `Widget._compose()` 内部方法撞名**（框架挂载 widget 时调用它，期望得到组件生成器，我返回了 Rich `Text`）。v0.2.0/0.3.0 的 TUI 改动只做了无头 `_compose()` 单测，没在真 App 挂载路径测过，漏检。

**修复**：`_compose` → `_build_render`（与 StatusBar 命名一致），代码/测试/.doc.md 同步。新增无头**挂载**冒烟测试（`/tmp/tui_mount_smoke.py`，`run_test()` 真挂载 + 模拟 phase_enter optimize → strategy_select → tool_result → optimize_fallback → phase_exit 全事件链），PASS；单测 10/10 保持。

**教训（已记入 tui/README.md 坑点）**：给 Textual widget 加方法时避开框架保留名（`compose`/`_compose`/`render` 等）；TUI 改动必须过一次 `run_test()` 真挂载冒烟，不能只测组合方法。
