### 2. 研读赛题 Docker 要求（关键澄清）
用户提示"仔细阅读比赛要求，我猜不需要打包 vitis"。全仓研读后确认：
- **FPT'26 Track A**（`Submission_Guidelines_Track-A.docx` 第 8 条）："Submissions are expected to be built and run within a Docker environment. A Dockerfile is **recommended** to be included"。Dockerfile 是推荐项非强制；赛方只给参考示例（anonymous 仓库 harness + vitis.dockerfile），**不提供 Vitis**。
- 官方 `vitis.dockerfile` 只装系统依赖库（gcc/cmake/python3 等），**根本不装 Vitis 本体**。其 `run-vitis.sh` 的模型是"宿主机装好 Vitis -> 只读挂载进容器用"。
- `config.py` 默认 `LLM4HLS_VITIS_HLS_ROOT=/opt/xilinx/2025.2/Vitis`，`vitis.py` 每次工具调用在子 shell 内 `source settings64.sh && exec vitis-run`，不需要 vitis-run 在容器 PATH 上。
- 仓库里 FPL'26 文档（`FPL26_runtime.md`/`FAQ.md`）提到"赛方预装 Vivado"，但那是另一个比赛，不适用本项目--易混淆点已记录。

**结论：不需要把 92G 的 Vitis 打进镜像。** 方案 = 镜像装依赖 + agent 代码，运行时挂载宿主机 Vitis。

### QFS-STATION 实测（2026-07-22 晚，P4-05 转 🟢）

**环境准备：**
- 服务器装 docker.io（v29.1.3）+ 配镜像加速器（docker.1ms.run 等，因 Docker Hub 不可达）
- rsync 同步本机 v0.7.4 代码到服务器（替换旧扁平结构）

**Build 过程踩坑（2 个）：**
1. Python 3.12 移除 distutils（PEP 632）-> distro pip 崩溃。解法：用 `python3.12 -m venv /opt/venv` 创建独立 venv，venv 自带兼容 3.12 的 pip。
2. pip 从 PyPI 下载 textual/rich 超时（files.pythonhosted.org 不可达）。解法：pip 加 `-i https://pypi.tuna.tsinghua.edu.cn/simple`。

**镜像内验证：**
- Python 3.12.13 + textual 0.86.2 + rich import OK
- Agent / harness / KB 模块导入全 OK，version 0.7.4

**运行时踩坑（1 个，关键）：**
- Vitis settings64.sh **硬编码兄弟目录绝对路径**（`source /home/admin/Xilinx/DocNav/...`、`/home/admin/Xilinx/2025.2/Vivado/...`）。最初只挂载 `Vitis` 子目录 -> source 报 "No such file" -> vitis-run 不在 PATH。
- 解法：挂载**整个 Xilinx 树**（92G，只读 bind mount）到容器内**相同路径** `/home/admin/Xilinx`，保持 settings64.sh 的硬编码路径生效。

**实测结果（两道题，csim/synth 真跑非 mock）：**

| 题目 | 类型 | csim | synth | SCORE | 与宿主机对比 |
|---|---|---|---|---|---|
| projection_bugfix | repair | pass (9.5s) | pass (23.1s, lat=0) | 1.400 | 一致 |
| dotProduct_optimize | optimize | pass (10.0s) | pass (25.6s, lat=36) | 3.000 满分 | 一致 |

两道题覆盖了 repair + optimize 两条路径，SCORE 与宿主机直跑完全一致。镜像内复现验证通过。
