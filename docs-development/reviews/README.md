# 评审记录 (Review Records)

本目录记录每一次需求评审、设计评审、测试用例评审的过程和结论。命名格式：`YYYY-MM-DD-<阶段>-review.md`，
例如 `2026-07-15-requirements-review.md`、`2026-07-15-design-review.md`。

## 记录模板 (Template)

```markdown
# <文档名称> 评审记录 第N轮

## 基本信息 (Meta)
- 评审对象 (Reviewed Document):
- 评审时间 (Date):
- 评审人 (Reviewer):

## 评审意见 (Comments)
| 编号 | 位置 | 意见 | 处理方式 | 状态 |
|---|---|---|---|---|
| 1 | ... | ... | ... | 已修订/待讨论/不采纳(原因) |

## 结论 (Conclusion)
- [ ] 通过，可进入下一阶段
- [ ] 需修订后再次评审
```

## 评审的实质

评审不是走过场。在真实项目中，设计评审发现了 5 处调用链断点（119 个事件中逐条核对发现的）。**评审是质量的关键防线**，不是橡皮图章。

- 每条意见都要记录处理方式（已修订 / 待讨论 / 不采纳及原因）。
- 结论必须明确：通过可进入下一阶段，或需修订后再次评审。
